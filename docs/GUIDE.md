# LDTF — подробное руководство

LDTF (Local DTF) — локальное приложение, которое делает копию профилей [DTF](https://dtf.ru):
- все посты пользователя со всеми блоками редактора и медиа;
- если нужно, все его комментарии со всего сайта с контекстом обсуждений (цепочка родителей и ответы) — выбор
  «Посты и комментарии» или «Только посты» делается при создании архива и меняется в его настройках;
- реакции и донаты;
- историю версий: правки, удаления и возвращения постов и комментариев на DTF;
- поиск по архиву.

Работает офлайн в браузере — на своём компьютере или на сервере в Docker, хранит данные в форматах, удобных для
скриптов, и подключается к ИИ-агентам по MCP. Использует только публичное API DTF, вход в аккаунт не нужен.

## Запуск

**Windows:** скачайте `LDTF-<версия>-windows-x64.zip` со страницы
[релизов](https://github.com/Gwynerva/ldtf/releases/latest) (не «Source code»), распакуйте целиком в постоянную папку
(например, `C:\LDTF`) и запустите `LDTF.exe`.
- LDTF запускается без консольного окна, значок появляется в трее, открывается **окно LDTF** — отдельное приложение
  на WebView2 (есть в Windows 10/11), со своим значком на панели задач. Окно одно: повторный запуск, значок в трее и
  уведомления выводят его вперёд. Ссылки на DTF и другие сайты открываются в обычном браузере. Окно помнит размер и
  положение, заголовок следует теме страницы. Закрыли окно — LDTF продолжает работать в трее.
  - «Настройки приложения → Открывать в отдельном окне» — выключите, чтобы LDTF открывался вкладкой браузера
    (`http://127.0.0.1:8765/`). Без WebView2 Runtime LDTF откроется в Edge в режиме приложения или в браузере.
- Python встроен в папку `runtime/`, ничего устанавливать не нужно.
- **Если LDTF не запускается, он говорит почему:** запуск прямо из zip-архива (Проводник распаковывает тогда один
  файл во временную папку — архивы пропали бы вместе с ней), папка без `runtime`, занятый порт, папка без прав записи,
  повреждённые файлы приложения — сообщение с тем, что сделать.
- `LDTF.exe` не подписан сертификатом, поэтому при первом запуске Windows может показать «Система Windows защитила
  ваш компьютер»: «Подробнее → Выполнить в любом случае».
- Из клона репозитория — `LDTF.cmd` (нужен Python 3.12+ или папка `runtime/`); `LDTF (консоль).cmd` — запуск в окне
  консоли, для отладки. Они проверяют, что найденный Python действительно запускается: ярлык «python» из Microsoft
  Store без установленного Python за него не принимается.
- С версии 1.3 на 1.4 обновитесь один раз вручную: распакуйте архив 1.4 поверх старой папки (архивы в `archive/` не
  тронутся, автозапуск сам переключится на `LDTF.exe`). Дальше LDTF обновляется из своих настроек.

**Значок в трее:**
- Цвет индикатора — состояние: зелёный — всё в порядке, синий — идёт синхронизация, красный — последняя синхронизация
  какого-то архива не удалась.
- Левый клик открывает LDTF.
- Правый клик — меню:
  - «Синхронизировать все архивы»;
  - «Автосинхронизация по расписанию» (пауза для всех архивов);
  - «Запускать вместе с Windows»;
  - «Настройки…»;
  - «Остановить LDTF» — идущие синхронизации сохраняют прогресс.

**Запуск с Windows и ярлыки** — в «Настройках приложения».
- Автозапуск — запись `LDTF` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`: `LDTF.exe --background` (в клоне
  репозитория — `runtime\pythonw.exe -m dtf_backup app --background`). LDTF тихо стартует в трее, первые синхронизации
  по расписанию — через пару минут после входа.
  - Если LDTF выключен в списке автозагрузки самой Windows («Параметры → Приложения → Автозагрузка», вкладка
    «Автозагрузка» диспетчера задач), запись остаётся, но Windows её пропускает — страница настроек предупреждает об
    этом; включить LDTF нужно там же, в Windows.
  - Запись следует за приложением, только если папку LDTF перенесли (программы по старому пути больше нет) или
    обновили: другая копия LDTF, запущенная ненадолго, автозапуск не перехватывает.
  - Каждое включение и выключение, а при старте — состояние автозапуска и то, как LDTF запущен (автозапуском или
    вручную), пишутся в `archive/.state/app.log` (строка «запущен в фоне» — старт автозапуском).
- Ярлыки «На рабочий стол» и «В меню Пуск» запускают `LDTF.exe` с его иконкой и без консоли.

**Сервер, NAS:** Docker или служба systemd — раздел [Сервер](#сервер). На своём Mac или Linux без Docker: клон
репозитория и `./ldtf.sh` (нужен Python 3.12+), приложение работает в терминале, без трея.

В приложении:
- **Добавить пользователя:** ник, id или ссылка, затем предпросмотр профиля, выбор «Что сохранять» и «Создать архив»:
  - **Посты и комментарии** — посты, все комментарии пользователя на DTF с контекстом обсуждений и медиафайлы. Первая
    выгрузка активного пользователя занимает от минут до пары часов, её можно остановить и продолжить с того же места;
  - **Только посты** — посты с медиафайлами, реакциями и счётчиками; комментарии не загружаются вовсе. Быстро и
    компактно; в архиве нет раздела «Комментарии», а под постом — ссылка на обсуждение на DTF.
- **Переключение архивов:** аватар с именем слева в шапке, как смена аккаунта; в списке — число постов и комментариев.
- **Управление архивом** (значок настроек справа в шапке) — вкладки:
  - «Синхронизация»: прогресс по стадиям, «Остановить», время следующей автосинхронизации; в меню «Ещё» — «Проверить
    всё заново» (заново скачать все посты и комментарии — часы для активного пользователя, обычно не нужно) и
    «Пересобрать страницы» (из скачанного, без сети; LDTF делает это сам после синхронизации и своего обновления);
  - «Настройки»: что сохранять (посты и комментарии / только посты), какие медиафайлы скачивать (все, только из
    постов, никакие), расписание автосинхронизации, проверка блоков (посты с блоками, которые LDTF показывает
    упрощённо или не знает — со ссылками прямо на блок), удаление архива.
- **Смена «Посты и комментарии» → «Только посты»** удаляет сохранённые комментарии. Сначала LDTF показывает, что
  уйдёт (сколько комментариев, веток, файлов медиа) и сколько места освободится, отдельно — комментарии, которые уже
  удалены на DTF и есть только в архиве. После подтверждения удаление идёт заданием на вкладке «Синхронизация»:
  строки базы, `raw/post-trees`, `raw/threads`, `raw/my-comments`, ссылки на медиа, затем файлы, которые больше не нужны
  ни одному архиву, и пересборка страниц. Намерение хранится в настройках: если LDTF закрыли на середине, удаление
  доделает следующий запуск или следующая синхронизация архива. Обратная смена скачает комментарии заново при
  следующей синхронизации.
- **Все настройки сохраняются сразу**, кнопки «Сохранить» нет: изменённый переключатель или поле записывается в
  тот же момент, короткое сообщение «Сохранено» это подтверждает. Отправляется только изменённая настройка, так что
  страница, открытая давно (или до перезапуска LDTF), не затрёт то, что поменяли в трее или в другой вкладке. Если
  сохранить не удалось (LDTF остановлен), переключатель возвращается в прежнее положение и появляется сообщение об
  ошибке. Каждое изменение пишется в `archive/.state/app.log`.
- **Настройки приложения** (в меню архивов) — вкладки:
  - «Основные»: запуск с Windows, ярлыки; пауза автосинхронизации для всех архивов; уведомления в трее;
    [обновления](#обновления); проверка совместимости с DTF; «Выйти» (на сервере с паролем); «Остановить LDTF»;
  - «Реакции»: какие реакции считать дизлайками ▼ — один список для всех архивов (`archive/reactions.config.json`).
    Страницы пересчитываются сразу, `data/` и `md/` архивов — в фоне через несколько секунд;
  - «ИИ-агенты»: подключение по MCP — см. [ИИ-агенты](#ии-агенты-mcp).

  Скорость и число параллельных запросов не настраиваются: LDTF подстраивает их под DTF сам (см. ниже).
- **Уведомления в трее** — только о важном: закончилась синхронизация, запущенная вручную или при создании архива;
  на DTF пропали свои посты или комментарии; защита архива остановила синхронизацию; синхронизация не удалась (один
  раз, не при каждом повторе). Плановые успешные синхронизации проходят молча.
- **Просмотр:**
  - посты (галереи, PhotoSwipe, спойлеры, все блоки редактора), дерево комментариев;
  - лента комментариев по месяцам, сгруппированная по веткам;
  - поиск по всему архиву;
  - [история версий](#история-версий) и «Изменения на DTF», [донаты](#донаты), каталог [«Блоки DTF»](#блоки-dtf).
- **Совместимость с DTF** (в настройках приложения): проверка, что DTF отвечает так, как ожидает приложение.
  Пригодится, если синхронизации стали заканчиваться ошибками.

## Расписание и общий лимит запросов

- **Расписание — у каждого архива своё:** «каждый день в ЧЧ:ММ» (местное время; у нового архива — 09:00), «каждые
  N часов» или «выключена».
  - Синхронизация, пропущенная из-за выключенного компьютера или сна, проходит сразу после запуска LDTF.
  - После неудачи (сеть, ограничения DTF) повтор идёт через 30 мин, 1 ч, 2 ч, 4 ч, 8 ч, без долбёжки.
- **Одновременно** идут задания двух архивов, у одного архива — только одно задание за раз (синхронизация, пересборка
  или удаление комментариев). Задания, запущенные вручную, идут раньше плановых.
- **Бюджет запросов к DTF один на всё приложение** (`dtf_backup/netpool.py`): до 10 запросов в секунду и 4 параллельных
  запроса к API, 8 параллельных загрузок медиа, сколько бы архивов ни синхронизировалось. Это не настройки: темп и
  параллельность снижаются сами на ответах 429 и ошибках и восстанавливаются после серии удачных запросов.
  - Ожидающие запросы обслуживаются по очереди, архивы делят бюджет поровну.
  - Ответ 429 или серия ошибок замедляют всех сразу: DTF ограничивает по IP.
  - Если DTF блокирует запросы, все синхронизации встают на паузу на 30 минут, потом осторожно продолжают.
- **Консоль.** `dtf-backup sync` при запущенном LDTF не качает сам, а отправляет задание в LDTF (тот же бюджет, прогресс
  печатается в консоли). `--standalone` — выполнить в своём процессе.
- **Параллельные синхронизации не мешают друг другу:**
  - у каждой свои временные файлы (`archive/media/.tmp/<ник>/`) и свой журнал;
  - файл, который нужен двум архивам сразу, скачивается один раз.

## Защита архива

DTF не удаляет материалы бесследно, а подменяет их заглушками: «Аккаунт удален», «Статья удалена», «Комментарий
недоступен». Обычная синхронизация перезаписала бы ими архив. LDTF этого не допускает (`dtf_backup/guard.py`).

- **Одиночные потери не останавливают синхронизацию.** В архиве остаётся прежняя версия с пометкой «удалён на DTF»,
  «стёрт на DTF», «пропал с DTF» или «недоступен на DTF». Это касается:
  - поста, который удалили, заменили заглушкой или стёрли правкой (текст ужался больше чем в 5 раз);
  - своего комментария, который удалили, скрыли или заменили на «.»;
  - чужого комментария в сохранённой ветке: автор удалил аккаунт, модератор, заморозка.

  Итог виден на вкладке «Синхронизация» («Изменения на DTF: пропало 1 пост, 3 комментария») и в уведомлении трея.
- **Подозрительное останавливает синхронизацию** до решения пользователя. Проверка идёт до записи: архив не меняется.
  Что считается подозрительным:
  - аккаунт удалён, заморожен или не найден. Если ник сменился, аккаунт находится по id, это не остановка;
  - разом пропало или стало заглушками много постов: от 3 и до 10 (10% архива);
  - за одну синхронизацию пропало 20 своих комментариев.

  На всех страницах архива появляется красный баннер, значок в трее краснеет, расписание для архива не запускается.
  На вкладке «Синхронизация» — причина, примеры со ссылками и кнопки:
  - **«Продолжить и сохранить удалённое»** — только для массовых потерь: пропавшее отмечается, старые версии остаются.
    В консоли то же делает `sync --accept-deletions`;
  - **«Проверить снова»** — если это был сбой DTF или аккаунт вернули.
- **Правки не теряются:** прежние версии постов и комментариев остаются в [истории](#история-версий).
- **В данных:** в `raw/` у сохранённых версий есть поле `_site: {state, at}`, в `data/*.jsonl` — `siteState`, в
  `view.sqlite` — `posts.site` и `siteState` комментариев, в `md/` — пометка курсивом.

## История версий

LDTF всегда показывает последнюю версию поста или комментария, которую видел, а каждую версию, которую заменила
правка на DTF, сохраняет в историю (`history` в `.state/state.sqlite`, модуль `history.py`). Туда же пишутся удаление
на DTF (как именно: автором, модератором, удалён аккаунт…) и возвращение.

- **Хранятся только изменившиеся версии**, сжатыми, без счётчиков и данных автора: версия поста — несколько КБ.
  Медиа — ссылками на общее хранилище: правка, в которой картинки остались прежними, новых файлов не добавляет, а
  картинки, которые правка убрала, остаются в архиве.
- **Версией считается смена содержимого** (заголовок, блоки, текст, вложения). Счётчики, реакции, донаты, «в сети» и
  другие живые данные новой версии не создают; одна правка, увиденная дважды (в ленте комментариев и в ветке), —
  одна запись.
- **Где смотреть:**
  - на посте — «изменён · N версий» → лента версий; у каждой — «Что изменилось» (блоки сопоставляются, в тексте
    подсвечено добавленное и удалённое, неизменное свёрнуто) и «Целиком»;
  - у комментария — «история» рядом с датой: все версии с подсвеченными правками;
  - «Изменения на DTF» (со статистики на «Главной»): все правки, удаления и возвращения архива с фильтрами;
  - «Удалённое на DTF» (плитка «удалено» на «Главной», строка на вкладке «Синхронизация», фильтр «Удаления»): только
    то, что сейчас удалено на DTF, — само содержимое, как оно было, и что с ним случилось (как и когда LDTF это
    заметил). Фильтры: посты или комментарии, свои или чужие.
- **С какого момента:** история ведётся с перехода на 1.4 (версии, которые LDTF 1.1–1.3 сохранял в `raw/history/`,
  переносятся в неё автоматически); более ранних правок LDTF не видел — страницы так и пишут.
- **Для агентов:** `data/history.jsonl`, таблица `history` в `view.sqlite`, инструмент MCP `get_history`.

## Целостность архива

Сбой питания, падение программы, антивирус или облачная синхронизация папки могут испортить файл. LDTF это замечает и
чинит сам, не выдавая чужую версию за свою (модуль `integrity.py`).

- **Опись.** Каждый файл `raw/` при записи попадает в опись (`files` в `.state/state.sqlite`): sha256, размер и дата
  содержимого; у постов и своих комментариев — ещё подпись сохранённой версии. Файлы и базы сбрасываются на диск
  до того, как заменить прежние.
- **Проверка перед каждой синхронизацией** (стадия «Проверка целостности», у архива petra — около 15 секунд):
  - все файлы `raw/` — по sha256 (файл, который отличается, читается: более новый, чью запись не успели отметить,
    принимается; нечитаемый или подменённый старой копией — повреждён);
  - база: структура (`PRAGMA quick_check`), каждый свой комментарий и каждая сохранённая версия распаковываются;
  - медиа: размер каждого файла и полное содержимое примерно седьмой части по кругу, сначала давно не проверенных
    (при ежедневных синхронизациях за неделю — все).
- **Починка — сначала локально:** зеркало `raw/` в `.state/backup/raw/` (точные байты на момент последней удачной
  синхронизации), копия в страницах (`view.sqlite`), экспорт своих комментариев `raw/my-comments/`. Копия, которая в
  точности та же версия, восстанавливает её молча.
- **Иначе — с DTF.** Лучшая уцелевшая копия ставится на место, а элемент скачивается заново и сравнивается с подписью
  версии, которая была в архиве: та же — восстановлено; на DTF уже другая — она становится текущей, а в истории поста
  или комментария появляется «Копия в архиве была повреждена» (уцелевшая более ранняя версия остаётся в истории
  обычной версией); на DTF нет вовсе — «восстановить не удалось». Повреждённый медиафайл скачивается заново; если на
  DTF теперь другой файл, это видно в отчёте.
- **Ничего не удаляется:** повреждённое переносится в `.state/quarantine/<время>/` (медиа — в
  `archive/.state/quarantine/media/`).
- **База.** Раз в день после чистой проверки `state.sqlite` и общий `media.sqlite` копируются в `.state/backup/`. Если
  база не проходит проверку, она уходит в карантин, на её место встаёт копия, а всё, что в повреждённой ещё читается
  (более новые строки), переносится в неё.
- **Страницы не собираются из повреждённых файлов:** перед сборкой опись сверяется ещё раз, найденное чинится.
- **«Проверить целостность»** на вкладке «Синхронизация» — полная проверка, включая каждый медиафайл (у petra —
  около минуты на 16 ГБ). Отчёт — там же: когда проверялось, что нашлось и чем кончилось. Если что-то нужно скачать,
  проверка сама продолжится синхронизацией. В консоли — `dtf-backup verify --user <ник>` (`--offline` — только
  локально).
- **«Скачать всё заново»** (меню «Ещё») — другое: заново скачивает с DTF все посты и комментарии и сравнивает с
  архивом (правки попадут в историю). Медиафайлы оно не перекачивает.

## Донаты

Каждая синхронизация читает ленту постов профиля, а в ней — свежие счётчики, реакции и донаты всех постов, даже тех,
что не менялись (сами посты перекачиваются только после правки). Поэтому цифры на страницах свежие.

- **На посте** — сумма донатов (её считает DTF); **донат-комментарий** (донат автору поста вместе с комментарием)
  выделен и подписан «Донат N ₽»; комментарий, которому донатили, — «+N ₽».
- **Страница «Донаты»** (со статистики на «Главной»): сколько получили посты, сколько пришло с комментариями, топ
  постов, кто донатил, лента донат-комментариев, донаты комментариям автора и донаты, которые отправил он сам.
  Итог — сумма DTF по постам; донат-комментарии её расшифровывают, а не добавляются к ней. У старых постов, где DTF
  показывает 0, сумма берётся по донат-комментариям.
- В списке постов есть сортировка «Донаты»; в `data/` — поля `donations`, `donation`, `donationsReceived`.

## Блоки DTF

Страница «Блоки DTF» (в меню архивов) показывает каждый тип блока редактора DTF так, как его показывает LDTF:
полностью, упрощённо (тексты, ссылки и медиа без оформления сайта) или «не поддерживается» (карточка с исходными
данными — ничего не теряется). Где в архивах блок уже есть, показан настоящий, иначе — образец; рядом — сколько раз
блок встречается и ссылки прямо на него в постах (`#b<номер>`). Фильтры: по уровню поддержки, по архиву, «есть в
архивах». Блок неизвестного LDTF типа, найденный в архиве, тоже попадает сюда.

Карточка «Проверка блоков» в настройках архива перечисляет его посты с такими блоками.

## ИИ-агенты (MCP)

LDTF — сервер [MCP](https://modelcontextprotocol.io): Claude, Cursor и другие клиенты ищут по архивам и читают их.
Только чтение — ни архивы, ни DTF агент не меняет. Инструменты: `list_archives`, `search` (`exact` — без
исправления опечаток), `count` (сколько комментариев, постов или найденного — по постам, авторам, годам, месяцам, дням),
`get_post` (с комментариями и прежними версиями, длинный — частями), `get_comment` (с веткой), `list_posts`,
`list_comments`, `get_history` (без id — лента всех правок и удалений), `archive_stats`. У чужого поста указан
автор, у поста другого архива библиотеки — его архив. Ответы — до 30 000 символов: длинные списки продолжаются через
`offset`. Протокол — обе редакции: 2026-07-28 и старая с `initialize` (2025-11-25, 2025-06-18, 2025-03-26).

- **На этом компьютере (stdio):** агент сам запускает `runtime\python.exe -X utf8 -m dtf_backup mcp` (LDTF при этом
  может быть не запущен). Готовые команды — в «Настройках приложения → ИИ-агенты», например для Claude Code:
  `claude mcp add --scope user ldtf -- "C:\LDTF\runtime\python.exe" -X utf8 -m dtf_backup mcp`.
  Нужен именно `python.exe`, не `pythonw.exe`. В папке релиза лежит `.mcp.json` с этой же командой: Claude Code,
  запущенный в папке LDTF, предложит подключить архивы сам.
- **По сети (HTTP):** запущенный LDTF принимает запросы на `http://<адрес>/mcp` с заголовком
  `Authorization: Bearer <токен>`. Токен — на той же вкладке (его можно выпустить заново); хранится в
  `archive/.state/mcp.token`, в Docker его можно задать переменной `LDTF_MCP_TOKEN`.
- **Docker:** HTTP-адрес или `docker exec -i ldtf python -m dtf_backup mcp`.

## Сервер

LDTF на сервере, NAS или VPS: веб-интерфейс на порту 8765 с паролем, синхронизации по расписанию, MCP по HTTP.
Два способа: Docker (любая система с Docker) или служба systemd (Linux с Python 3.12+).

### Docker

Образ `ghcr.io/gwynerva/ldtf` (amd64 и arm64), архивы — в томе `/data`. В репозитории — готовый `compose.yaml`:

```
curl -O https://raw.githubusercontent.com/Gwynerva/ldtf/main/compose.yaml
echo LDTF_PASSWORD=придумайте-пароль > .env
docker compose up -d                          # http://<адрес сервера>:8765
docker compose pull && docker compose up -d   # обновление: архивы в ./data остаются
docker compose exec ldtf python -m dtf_backup status --user <ник>
```

- **https с доменом:** DNS домена должен указывать на сервер; в `.env` добавьте `LDTF_DOMAIN=ваш.домен` и
  `LDTF_PUBLISH=127.0.0.1:8765` (тогда LDTF без https снаружи не виден) и запускайте
  `docker compose --profile https up -d`: перед LDTF встаёт Caddy и сам получает и продлевает сертификат.
- **Права на папку:** контейнер стартует от root ровно настолько, чтобы отдать `./data` пользователю
  `LDTF_UID:LDTF_GID` (по умолчанию 1000:1000; папку, которую создал Docker, он создаёт от root), и запускает LDTF от
  этого пользователя. С `user:` в `compose.yaml` или `--user` LDTF просто запускается от него.
- **Остановка:** `docker stop` даёт синхронизациям сохранить прогресс (SIGTERM, `stop_grace_period: 30s`).

### Без Docker: служба systemd

Debian 13, Ubuntu 24.04 и новее (нужен Python 3.12+; в Debian 12 — 3.11, там используйте Docker). От root:

```
curl -fsSLO https://github.com/Gwynerva/ldtf/releases/latest/download/install.sh
sudo sh install.sh                        # http://<адрес сервера>:8765
sudo sh install.sh --domain ваш.домен     # сразу с https через Caddy
```

- `install.sh` скачивает `LDTF-<версия>-linux.tar.gz` последнего релиза, сверяет его с `SHA256SUMS`, создаёт
  пользователя `ldtf`, кладёт приложение в `/opt/ldtf`, архивы — в `/var/lib/ldtf`, настройки — в
  `/etc/ldtf/ldtf.env` (адрес, порт, пароль — его install.sh создаёт и печатает в конце) и запускает службу
  `ldtf.service` (`Restart=always`). Журнал: `journalctl -u ldtf -f`.
- `--domain`: LDTF слушает только сервер, перед ним Caddy (ставится из пакетов дистрибутива) с сертификатом для
  домена. `--local`: только сервер — для своего обратного прокси. `--port`: другой порт.
- **Обновления — кнопкой** в «Настройках приложения» (см. [Обновления](#обновления)) или `sudo sh /opt/ldtf/install.sh
  --update`.

### Пароль, адрес и прочее

- **Пароль обязателен**, когда LDTF слушает не только этот компьютер (в Docker — всегда): `LDTF_PASSWORD` (или
  `LDTF_PASSWORD_FILE` для секретов Docker). Без него сервер не запустится. Вход — страница пароля, сессия на 30 дней
  (cookie), после нескольких неверных паролей попытки замедляются. Если вход уже проверяет обратный прокси, задайте
  `LDTF_AUTH=off`. За https-прокси cookie получает флаг Secure сам (по `X-Forwarded-Proto`).
- **Без пароля открыты** только `/healthz` (проверка здоровья), страница входа, стили и `/api/ping`; `/mcp` и API
  заданий консоли защищены своими токенами.
- **Время:** `TZ` (по умолчанию `Europe/Moscow`) задаёт, когда наступает «каждый день в 09:00».
- **Переменные:** `LDTF_ROOT`, `LDTF_HOST`, `LDTF_PORT` — папка архивов, адрес и порт (список — в
  `dtf_backup/config.py`). Порт, заданный явно, занимается ровно он; без него LDTF берёт 8765 или следующий свободный.
- Вручную, без install.sh: `python -m dtf_backup serve --host 0.0.0.0 --port 8765` с `LDTF_PASSWORD`.

## Обновления

Раз в день (переключатель «Проверять обновления автоматически» в настройках) LDTF спрашивает GitHub, вышла ли новая
версия; без интернета проверка тихо пропускается. О новой версии сообщают точка на переключателе архивов, пункт в меню
трея и одно уведомление. Карточка «Обновления» в настройках показывает, что нового, и как обновиться:

- **Версия для Windows из архива релиза** — кнопка «Обновить до X». LDTF скачивает архив релиза и `SHA256SUMS` (только
  с GitHub по HTTPS), сверяет контрольную сумму и состав (`release.json`), ждёт окончания идущих синхронизаций (или
  останавливает их по кнопке — прогресс сохраняется) и передаёт работу помощнику (`dtf_backup/selfupdate.py`, он
  запускается из новой версии). Помощник дожидается выхода LDTF, переносит старые файлы в `.update/backup/`, копирует
  новые, запускает `LDTF.exe` и ждёт, пока новая версия ответит. Если она не ответила за минуту — всё возвращается и
  запускается прежняя версия. `archive/` при обновлении не трогается. Папка `runtime/` заменяется, только если в новой
  версии другой Python; файлы, которые держит запущенный агент MCP, переименовываются и удаляются при следующем
  запуске. Ход — в `.update/update.log`, итог — баннер в настройках.
- **Сервер без Docker (`install.sh`, systemd)** — та же кнопка. LDTF скачивает `LDTF-<версия>-linux.tar.gz` и
  `SHA256SUMS`, сверяет, ждёт синхронизации, переносит свои файлы в `.update/backup/`, кладёт новые и завершается;
  systemd запускает новую версию. Если она дважды не запустилась, `ldtf-run.sh` возвращает прежнюю, и та показывает,
  что обновление не удалось. Если LDTF запущен не службой systemd — команда `sudo sh /opt/ldtf/install.sh --update`.
- **Docker** — в папке с `compose.yaml`: `docker compose pull && docker compose up -d` (контейнер не может заменить
  собственный образ; карточка показывает эту команду). **Клон репозитория** — `git pull` и перезапуск.
- **Окно LDTF** (Windows) закрывается вместе со старой версией и открывается снова новой.

## Консольный режим (для скриптов и агентов)

```
dtf-backup sync --user petra        # докачать новое (затем render); при запущенном LDTF — через него
dtf-backup sync --user petra --full # скачать всё заново (медиа не перекачиваются)
dtf-backup verify --user petra      # проверить целостность целиком, повреждённое восстановить; --offline — без сети
dtf-backup sync --user petra --standalone --workers 2   # в своём процессе, со своими ключами
dtf-backup sync --user petra --standalone --media posts # медиа только из постов (all | posts | off)
dtf-backup sync --user nick --scope posts               # новый архив: только посты (запоминается)
dtf-backup sync --user petra --scope posts --drop-comments   # переключить архив и удалить его комментарии
dtf-backup render --user petra      # пересобрать view.sqlite, md/, data/ без сети
dtf-backup status --user petra      # прогресс и статистика
dtf-backup check-api                # живая проверка API DTF (таблица ✓/✗ с подсказками)
dtf-backup mcp                      # MCP-сервер для ИИ-агентов через stdio (только чтение)
dtf-backup app                      # то же, что LDTF.exe (трей); --background — без окна
dtf-backup serve --open             # без трея, в консоли; --host 0.0.0.0 --port 8765 — сервер (нужен LDTF_PASSWORD)
```

Без `.cmd`: `python -X utf8 -m dtf_backup <команда>` из папки приложения.
`--user 136492` (числовой id) находит архив этого пользователя, даже если папка названа по нику.

## Как это устроено

- **Синхронизация:** стадии `integrity → profile → posts → comments → threads → media`; у архива «Только посты»
  (`scope: "posts"` в `.state/settings.json`) — `integrity → profile → posts → media`, без деревьев комментариев под
  постами. Первая стадия — проверка целостности (`integrity.py`, раздел [Целостность архива](#целостность-архива)).
  Прогресс хранится в `archive/<ник>/.state/state.sqlite`; каждая единица работы сохраняется сразу, поэтому после
  остановки или падения работа продолжается с места.
- **Перепроверка свежего:** каждая синхронизация перечитывает ответы, счётчики и удалённые комментарии за последние
  30 дней (`refresh_days` в `.state/settings.json`, в консоли `--refresh-days`; в приложении не настраивается).
- **Сеть:** постоянные keep-alive соединения (частые новые TLS-соединения DTF обрывает), общий бюджет запросов на всё
  приложение. На HTTP 429 темп снижается сам, при ошибках делается пауза с нарастанием.
- **Комментарии:** первичная выгрузка идёт параллельно по месяцам, докачка — от новых к уже известным.
- **Контекст:** для комментариев в чужих постах сохраняются предки до корня и всё поддерево ответов. Под постами
  пользователя сохраняются полные деревья комментариев.
- **Медиа:** общее хранилище `archive/media/<sha256>.<ext>`.
  - Дедупликация: uuid, затем Range-проба 64 КБ начала и конца файла, затем sha256.
  - Файлы, уже скачанные для другого архива, повторно не качаются.
  - Что скачивать — настройка архива «Медиафайлы» (`media` в `.state/settings.json`, в консоли `--media`):
    - **Все** (по умолчанию): медиа постов, своих комментариев, деревьев под своими постами и чужих комментариев в
      сохранённых ветках, аватарки и реакции. Архив полностью открывается без интернета;
    - **Из постов:** медиа постов, профиль, аватарки, иконки реакций и значков. Картинки, гифки и видео из
      комментариев не качаются — их показывает DTF, пока он доступен. Уже скачанное остаётся; при возврате на «Все»
      пропущенное докачается при следующей синхронизации. На вкладке «Синхронизация» видно, сколько файлов пропущено.
      У архива «Только посты» этого варианта нет: там «Все» и так означает медиа постов;
    - **Не скачивать.**

    Ссылки на медиа записываются в очередь всегда (`media_use` с владельцем `post:`, `mc:`, `pc:`, `tc:`, `avatar:` …),
    настройка решает только, что скачать (`media.owner_sql`).
  - **Файл не в архиве** страница берёт с DTF и помечает значком «с DTF». Если загрузить его не удалось (нет сети,
    CDN лежит, файл удалён), на его месте появляется заглушка того же размера с кнопкой «Повторить»
    (`assets/app.js`, ошибки ловит слушатель в `<head>`, поэтому ленивые картинки тоже). Файл, на который DTF при
    скачивании ответил 403/404/410/451, сразу показывается заглушкой «Удалено с DTF» — без запроса к CDN; «Попробовать
    загрузить» запрашивает его по кнопке. Аватарка при ошибке становится значком человека, обложка профиля —
    фоном, иконка реакции — кружком.
  - **Удаление архива или его комментариев** убирает из хранилища файлы, которые больше не нужны ни одному архиву.
    Очистка идёт, когда не работает ни одно задание, и на это время новые не стартуют: LDTF держит блокировку
    синхронизации всех архивов. Если архив синхронизирует другой процесс или база какого-то архива не читается, ничего
    не удаляется, а очистка откладывается (`archive/.state/gc-pending`) до момента, когда задания закончатся.
- **Без интернета:** все страницы, поиск и медиа работают из локальных файлов. Синхронизация за несколько секунд
  сообщает «нет подключения к интернету» и ничего не меняет в архиве; по расписанию она повторится позже.
  Проверено в Docker с `--network none`.
- **Просмотр:** страницы собираются на лету из `view.sqlite`. Неизвестные блоки редактора сохраняются
  как есть и показываются плашкой с JSON. После обновления LDTF, изменившего сборку (`VIEW_FORMAT` в `viewdb.py`),
  архивы пересобираются сами при запуске, по одному.
- **Интерфейс:** Material Design 3, светлая и тёмная тема.
  - Шапка одна на всех страницах: переключатель архивов, разделы, прогресс синхронизации, «Управление архивом» и тема.
  - На телефоне разделы переносятся в нижнюю панель.
  - Иконки — Material Symbols (Google, Apache License 2.0), встроены в `web/icons.py`; сеть для них не нужна.
- **Поиск:** FTS5 по постам и комментариям.
  - Индексируются исходные слова и их основы: русский Snowball плюс «именная» основа, английский Porter.
  - Словарь слов с триграммным индексом используется для исправления опечаток.
  - Подробности ниже.
- **Безопасность:** по умолчанию сервер слушает только `127.0.0.1` и принимает лишь локальный заголовок Host (защита
  от DNS rebinding); действия защищены CSRF-токеном и проверкой Origin. На сервере (`--host`, Docker) — пароль и
  сессии (`web/auth.py`), действия — только со своего адреса. JSON-API заданий для консоли требует токен запуска из
  `app.run.json`, `/mcp` — свой токен.

### Поиск

Страница «Поиск» в архиве. Синтаксис (он же в подсказке «Как искать» под полем):

| Запрос | Что найдёт |
|---|---|
| `катана` | все формы слова (катану, катаной) и слова, которые с него начинаются |
| `"точная фраза"` | слова в таком виде и порядке |
| `-слово`, `-"фраза"` | исключить документы с ними |
| `игра OR фильм`, `игра \| фильм`, `игра ИЛИ фильм` | любое из слов |
| `косп*` | только по началу слова, без морфологии |

- **Исправления.**
  - Автоматически исправляются латинские буквы внутри русских слов (`каcплей`), неверная раскладка
    (`rjcgktq` → косплей) и опечатки: 1 правка в словах до 7 букв, 2 — в более длинных; перестановка соседних букв
    считается одной правкой.
  - Исправление срабатывает, только если написанного слова нет в архиве. Ссылка «Искать как написано» отключает
    исправления (`&exact=1`).
  - Если найдено мало, а у похожего слова в архиве много употреблений, появляется подсказка «Возможно, вы искали».
- **Ранжирование.** bm25 с весами: заголовок выше текста, точная форма слова выше совпадения по основе.
  - Первыми идут документы, где все слова стоят рядом.
  - Посты пользователя выше его комментариев, его комментарии выше чужих.
  - Есть сортировка по дате, фильтры по типу и году.
- **Результаты.** По умолчанию сгруппированы по постам. У ответа показывается комментарий, на который он отвечает.
  Подсвечиваются все формы слова. Ссылка ведёт прямо к комментарию.
- **Для агентов.** `from dtf_backup.search.engine import search; search(sqlite3.connect(".state/view.sqlite"), "запрос")`
  возвращает `Result` с `total`, `hits` (kind/ref/entry/date/title/body), `notes`, `suggestion`. `prepare(db, "запрос")`
  даёт то же условие для своего SQL (`FROM {Match.FROM} WHERE {where}`), `other_forms` — формы слов, которых запрос не
  находит.

## Тесты

- `python -m unittest discover -s tests` — офлайн.
- `DTF_LIVE=1 python -m unittest tests.test_live_api` — через сеть.
- Проверка целостности архива: `python tests/verify_archive.py archive/<ник>`.
- Иконки: `python tools/make_icons.py` перегенерирует `dtf_backup/assets/brand/`; `python tools/material_icons.py <имя>`
  добавляет значок Material Symbols в `web/icons.py`.
- Сборка релиза для Windows: `python tools/build_release.py` (zip с `LDTF.exe` и `SHA256SUMS` в `dist/`). Релиз целиком —
  zip, образ Docker и страницу релиза — собирает GitHub Actions по тегу `vX.Y.Z` (`.github/workflows/release.yml`),
  описание берётся из раздела версии в `CHANGELOG.md`.
